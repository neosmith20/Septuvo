- **Objective:** the Septuvo VPN desktop application for Linux, built **exactly to the owner-approved designs**, on the service from N2–N3, written in Rust (D-005):
  - **Simple mode** ([DEFAULT-UI.md](../ui/desktop/DEFAULT-UI.md), `Default_VPN_UI.png`), the default;
  - **Advanced mode** ([ADVANCED-UI.md](../ui/desktop/ADVANCED-UI.md), `Advanced_VPN_UI.png`).

  The service gains what those designs need: saved connections and switching, Lockdown Mode, Local Network Access, DNS settings and diagnostics.
- **Relationship to the roadmap:** an **early, lab-only Linux slice of M7-01/M7-02**. The same designs are the targets for Windows and macOS in M7 (D-037). Signed packages and a real tunnel come later.
- **Reconciliation record:** [desktop-ui-reconciliation.md](../reviews/desktop-ui-reconciliation.md) lists every earlier statement this revision replaces.

## The binding designs

- **Do not redesign, rearrange, add or remove** any element of either main window. Text and widgets are real and accessible; the reference images are never drawn as pictures of a UI.
- **Every state is truthful.** Before G1 the app never shows **Protected** or **You're Connected**, a green check, a connection timer, a public IP or a location. It shows the pre-G1 state **VPN Not Yet Available**, or the true lab state (for example the kill switch blocking).
- **Missing backend features are not permission to improvise.** They are shown as not available, or the agent stops and asks.

## The Rust rule (D-005)

**All Septuvo-authored VPN and Server software is written in Rust**: this app, its UI, the service and the installer. The implementation language of external components is not restricted, but each one is reviewed before adoption (D-015).
- **Every non-Rust native component** the app brings in is listed and justified in N4-01's review, and the CI gate fails on any that is not.
- **No Septuvo-authored non-Rust code during N4.**

## The G1 boundary (unchanged)

**Not allowed:**
- an SVP handshake, packet encryption or wire encoding;
- key generation or management;
- usable invitations or enrollment;
- functional protocol transport;
- **any cryptography crate in Septuvo's code**, including a TLS library.

So **DNS over HTTPS/TLS and update checks are not built in N4**: they need the TLS client decision ([reconciliation](../reviews/desktop-ui-reconciliation.md) open decision 1). Their controls are shown as **Not available yet**.

**Still lab-only.** The app talks to the lab-mode service, which runs only in its lab network namespace (N3-01). Encryption-related settings stay read-only (DEFAULT-UI §6.3).

## Architecture

```text
 Septuvo VPN (desktop app, unprivileged user)           septuvod (root, lab namespace)
 ┌──────────────────────────────────────────────┐       ┌────────────────────────────────────┐
 │ Simple and Advanced windows (egui/eframe,    │       │ kill switch, DNS, captive portal   │
 │ AccessKit) · tray · notifications · native   │◀────▶│ + saved connections and switching  │
 │ Open/Save dialogs · app preferences          │  IPC  │ + Lockdown Mode, Local Network     │
 │ view model (plain Rust) · septuvo-ipc client │       │   Access, DNS settings, DIAGNOSE   │
 └──────────────────────────────────────────────┘       └────────────────────────────────────┘
   Linux OS interfaces: display server, keyboard layouts, OpenGL driver,
   D-Bus (tray host, notifications, xdg-desktop-portal, AT-SPI)
```

**Principles:**
- **The service is authoritative.** Connections, the kill switch, Lockdown Mode, Local Network Access and DNS settings are stored and enforced by the service and shown as it reports them. The app validates for instant feedback; the service validates again.
- **One implementation, two presentations (D-037).** Both modes use the same view model, connection management, settings, diagnostics and policies. **Switching modes never touches the connection.**
- **Closing (D-041, replacing D-019).**
  - Minimize never disconnects.
  - X with the default **Exit and Disconnect** makes a deliberate disconnect through the service, then exits.
  - X with **Send to System Tray** hides the window and keeps the connection.
  - **The GUI ending for any other reason changes nothing in the service.**
  - With Lockdown Mode on, blocking continues after the disconnect.
- **Least privilege.** The app runs as the user, **refuses root**, and changes things only through the control socket (membership of the `septuvo` group). **No `sudo`, `pkexec` or polkit.**
- **Untrusted input everywhere.** Service responses, imported files and diagnostics are plain text; nothing is interpreted as markup, links or commands.

### N4-03 — Service: saved connections, selection and switching

- **Outputs:** `crates/septuvo-ipc/`, `crates/septuvo-daemon/`, `crates/septuvo-config/`, `crates/septuvo-cli/`, `tests/lab/namespaces/`, `fuzz/`, `docs/build/daemon.md`, `docs/build/config.md`.
- **Work:**
  - **A service-owned store of complete connections (N4-D11).**
    - Commands to list, get, add, replace, rename, delete and select connections.
    - Requests carrying a connection use a **length-prefixed body of at most 64 KiB**: the protocol's one exception to the 64-byte request limit, specified and fuzzed.
    - Changes are validated by `septuvo-config`, then written atomically.
  - **Switching while connected (D-041):**
    1. end the old session;
    2. **replace the ruleset in one nftables transaction, with protection kept throughout**;
    3. start the new session;
    4. report the result.

    Failures keep the new selection, block (fail closed) and never silently reconnect the old one.
  - **Status fields for every approved state:** connecting, switching, disconnecting, reconnecting, failed with reason, the active connection, verified kill-switch and DNS values for the tiles, and the time of verification.
  - **Configuration file changes:**
    - `behavior.always_on` is retired (D-038);
    - `dns.mode = "system"` is refused in split mode until per-domain DNS exists (NP-D10).
  - **CLI:** `septuvo connection …` and `septuvo connect NAME`.
- **Acceptance:**
  - IPC, engine and fuzz tests (standard library and cargo-fuzz);
  - **lab case T2-SW-01**: a switch while connected never lets a packet out outside the policy;
  - a bad connection changes nothing.

### N4-04 — Service: Lockdown Mode and Local Network Access

- **Outputs:** `crates/septuvo-policy/`, `crates/septuvo-daemon/`, `crates/septuvo-ipc/`, `crates/septuvo-cli/`, `packaging/linux/`, `tests/lab/namespaces/`, `tests/lab/install/`, `docs/build/`, `desktop/`.
- **Work:**
  - **Lockdown Mode (D-038, NP-K1–NP-K5):**
    - a service setting, default off;
    - a blocking ruleset with only the NP-K2 exceptions;
    - kept after a deliberate disconnect and across service restarts;
    - **installed at boot before the network is configured** (a systemd unit ordered before `network-pre.target`);
    - removed only by turning it off, the documented administrator recovery command, or uninstall.
  - **Local Network Access (D-040, NP-L1–NP-L7):**
    - a service setting, default Not Allowed;
    - the directly attached subnets are computed from the interface's own addresses, with the size caps and overlap rules;
    - recomputed on every address change;
    - discovery stays blocked.
  - **The app:** the Advanced **Local Network Access** tile becomes operable (confirmed by the service, with the one-line note when allowing).
- **Acceptance:**
  - **lab cases T2-LD-01 and T2-LAN-01**: blocking after disconnect, service kill and restart; boot ordering in the install test; hostile DHCP/RA-sized prefixes, overlapping prefixes and discovery traffic stay blocked;
  - uninstall removes everything;
  - the independent-review items in reconciliation section 5 are listed in the PR.

## Not in N4

- **DNS over HTTPS and DNS over TLS**, and **update checks**: after the TLS client decision, in a new work order.
- **Automatic update installation:** G3 (signed builds, S-12).
- **Public IP, server location, real connection states, enrollment:** after G1 (M5, M6).
- **Captive-portal control in the UI:** not in the approved designs; stays a CLI feature (reconciliation C19).
- **Windows, macOS** (M7, same designs) and mobile.
- **polkit** or other privilege prompts.

## Stop points

- **Each task:** a pull request awaiting the owner's review. N4-01 and N4-02 also wait for the owner's **visual sign-off** against the reference images.
- **N4-01's hero artwork** waits for N4-D9 (source art or an approved rendering plan).
- **Stop and ask the owner** if a task appears to need:
  - **any change to an approved design**, or a behaviour the specifications do not define;
  - Septuvo-authored non-Rust code, or a native component not in the review;
  - cryptography (including TLS);
  - a crate not approved in N4-01's review;
  - `unsafe` in Septuvo's code;
  - privilege escalation;
  - a change outside the lab namespace on a real machine;
  - a licensing decision not covered here.
- **After N4-09 is merged, N4 is complete.** Nothing beyond N4 starts without a new work order.
