**Status:** proposed. **Authorization (D-031, category B):** the owner's merge of the pull request that adds this file authorizes N2-01 to N2-04. After each task's pull request is merged, the agent continues with the next task without a new go-ahead (D-034).

- **Task ID / milestone:** N2 (covers N2-01 to N2-04 in [TASK_CATALOG.md](../TASK_CATALOG.md))
- **Predecessor:** N1 accepted (PRs #29, #45)
- **Required gate:** G0 passed (#25). **G1 is not required, because nothing in N2 is cryptographic** (D-029). G1 stays **NOT PASSED** and continues to block all protocol and cryptographic code.
- **Objective:** real, tested Rust code for the parts of Septuvo VPN and Septuvo Server that do not depend on the protocol:
  - configuration;
  - DNS enforcement;
  - the privileged/unprivileged split;
  - server device records.

  When G1 passes, the reviewed protocol plugs into a working application.

## The G1 boundary (applies to every N2 task)

**Not allowed in N2:**
- SVP handshake, packet encryption, wire-format encoding or decoding;
- key generation, key storage or any other key management;
- usable invitations or enrollment;
- any functional protocol transport, and any socket that carries tunnel traffic;
- any cryptography crate.

Where later protocol work will connect, N2 defines **explicit interfaces with placeholder implementations only**, under these rules:

| Rule | How it is enforced |
| --- | --- |
| Every placeholder returns an error such as `NotAvailableBeforeG1`. It never pretends to succeed | Unit tests |
| Status never shows "peer authenticated" or "connected" through a placeholder (D-020) | Tests in `septuvo-cli` and the daemon |
| Placeholder fields are typed as placeholders (for example `PlaceholderKey`), cannot be used where a real key would be, and are labelled "not a key" in all output | Type system and tests |
| No document, help text or status message claims security that does not exist | Review |

## Dependencies, toolchain and environments

- **No third-party crates:** standard library only, as in N1. The CI check that rejects any third-party crate in `Cargo.lock` stays in force. Adding a dependency would need a revised work order.
- **No `unsafe`:** `unsafe_code = "forbid"` stays.
  - Consequence: the daemon cannot read socket peer credentials, which needs `unsafe` or a third-party crate. Access control therefore uses **socket file permissions** (N2-02), a common, well-understood method.
- **Toolchain:** the pinned `rust-toolchain.toml` (1.99.0).
- **Environments:**
  - unit tests anywhere;
  - firewall, DNS and daemon tests run **only in throw-away network namespaces** on disposable CI runners or an owner lab VM, as in N1-03.
  - **No change to any real host, router, firewall or DNS configuration, and no internet traffic.**
  - The daemon refuses to change firewall or DNS state unless its configuration sets `mode = "lab"` **and** it runs in a network namespace other than the host's. This guard is tested.

## Tasks

### N2-01 — Configuration format, parser and validation

- **Outputs:**
  - `crates/septuvo-config/`;
  - `docs/build/config.md`;
  - example files in `crates/septuvo-config/examples/`.
- **Format:** a **strict subset of TOML**, parsed with the standard library:
  - `[table]` headers;
  - `key = value`;
  - strings, integers, booleans and arrays of strings;
  - comments.

  Any valid Septuvo file is valid TOML, so a full TOML parser could replace ours later without changing users' files.
- **Two schemas:**
  - **Device** (`septuvo.toml`): server endpoint(s), mode (full tunnel or LAN-only, D-027), LAN exceptions, split prefixes and DNS policy, using the `septuvo-policy` model. The pinned server identity is a placeholder field.
  - **Server** (`septuvo-server.toml`): listen address and port (stored only, nothing is opened), tunnel address ranges (Q13), log retention (Q10) and the data directory.
- **Validation (hostile input):**
  - size and line-length caps;
  - unknown keys and duplicate keys rejected;
  - typed values with ranges;
  - IPv4 and IPv6 prefixes checked;
  - overlapping or contradictory settings reported;
  - errors give file, line and column;
  - **never a silent default for a security setting**: an absent kill-switch or DNS policy means the safe default (blocking), not "off".
- **CLI:** `septuvo config check FILE` added to the Apache-2.0 CLI by reading the file through `septuvo-ipc` types, or `septuvo-server config check FILE` on the server side. Which one is settled in the pull request without crossing the license boundary.
- **Acceptance:**
  - table-driven tests for every rule;
  - deliberately broken files (truncated, binary, very long lines, deep nesting, duplicate tables, wrong types, out-of-range values) are rejected without panics;
  - the examples parse;
  - `cargo test` passes in CI.

### N2-02 — Privileged service and unprivileged control interface

- **Outputs:**
  - `crates/septuvo-ipc/`;
  - `crates/septuvo-daemon/`;
  - `septuvo` CLI changes in `crates/septuvo-cli/`;
  - `docs/build/daemon.md`.
- **Design** (ARCHITECTURE: separate privileged daemon and unprivileged UI; identity-and-privacy AD-4):
  - `septuvod` is the only component that changes network state (kill switch, DNS). The CLI never does.
  - Two Unix sockets:
    - **status**: readable by any local user, read-only requests;
    - **control**: owner `root`, group `septuvo`, mode `0660`; accepts connect, disconnect and policy reload.

    The socket directory is created with safe permissions, and existing files of the wrong owner or type are refused.
  - The request/response format is a small, versioned, line-based text protocol defined in `septuvo-ipc`. Its limits:
    - request size capped;
    - one request per connection;
    - timeouts;
    - unknown commands rejected;
    - every field validated as hostile input (ADV-10).
  - **"Connect" uses the placeholder tunnel interface.** It applies the kill switch (from N1) and reports stage 1 at most. Peer authentication stays `Fail: not available before G1` (D-020).
  - Clean shutdown keeps blocking unless the user disconnected deliberately (Q2). A crash leaves the rules in place (fail closed).
- **Acceptance:**
  - unit tests for the protocol parser (malformed, oversized, unknown, slow client);
  - a namespace integration test in CI:
    - start `septuvod` in lab mode;
    - `septuvo status` works as an unprivileged user;
    - control requests from a user outside the `septuvo` group are refused;
    - connect applies the kill switch (the existing leak probes pass);
    - disconnect removes it;
    - killing the daemon leaves blocking in place;
  - a test that the daemon refuses to run outside lab mode or in the host namespace.

### N2-03 — DNS policy enforcement and leak tests

- **Outputs:**
  - DNS rule generation in `crates/septuvo-policy/` (extends the N1 nftables renderer, Apache-2.0);
  - DNS configuration handling in `crates/septuvo-daemon/`;
  - new cases in `tests/lab/namespaces/`;
  - `docs/build/lab.md` updates.
- **Behaviour** (network-policies.md, D-032 Q1–Q3):
  - In full-tunnel mode, DNS is allowed **only to the configured tunnel resolver(s), over the tunnel interface**. These are blocked:
    - UDP and TCP port 53 to anything else;
    - DNS over TLS (853) to anything else;
    - IPv6 and IPv4 alike.
  - The daemon writes the namespace's resolver configuration (in the lab, `/etc/netns/<name>/resolv.conf`) and restores it on deliberate disconnect.
  - Optional LAN DNS exceptions apply only when explicitly configured.
  - **DNS over HTTPS cannot be blocked by port.** This limit is documented, not hidden.
- **Acceptance:** new namespace cases with token probes:
  - queries to the underlay resolver are blocked (UDP, TCP, DoT, IPv4 and IPv6);
  - queries to the tunnel-side resolver through the tunnel interface are allowed;
  - a configured LAN DNS exception works, and only for its address;
  - the resolver file is restored after disconnect, and left blocking after a crash;
  - all existing N1-03 cases still pass, including `--require-ipv6` in CI.

### N2-04 — Server administration foundations

- **Outputs:**
  - `crates/septuvo-server/`;
  - `docs/build/server-admin.md`.
- **Commands** (`septuvo-server`, run locally by the administrator; AD-1, no network API):
  - `device add NAME --scope home|exit|both`;
  - `device list`;
  - `device show NAME`;
  - `device revoke NAME`;
  - `device remove NAME`;
  - `config check`.
- **Device record:**
  - name;
  - scope;
  - assigned tunnel addresses, allocated from the configured ranges without collisions;
  - created and revoked times;
  - **a `PlaceholderKey` field marked "not a key — enrollment not available before G1"**.
- **Storage:**
  - one data file, written atomically (temporary file, flush, rename) with mode `0600`;
  - a version field;
  - corruption or an unreadable file means **refuse everything** (RV-2, fail closed), never "start empty";
  - revocation survives restarts (RV-1);
  - local action log without secrets (AD-2, PR-2).
- **Not included:** invitations, enrollment, keys, the network listener. `device add` creates a record that **cannot connect** until reviewed enrollment exists, and the output says so.
- **Acceptance:**
  - unit tests for each command;
  - address allocation (exhaustion, IPv4 and IPv6);
  - an interrupted write leaves the old file intact (simulated crash between write and rename);
  - a corrupted file is refused;
  - concurrent invocations are serialized with a lock file;
  - names are validated as hostile input.

## Risks

| Risk | Handling |
| --- | --- |
| Placeholders mistaken for working security | Typed placeholders, error-only behaviour, honest status, tests (boundary table above) |
| Daemon changes a real machine | Lab-mode and namespace guard, tested; CI runs only on disposable runners |
| Hand-written parser bugs | Strict subset only, size limits, table-driven and malformed-input tests; no `unsafe` |
| Socket permission mistakes | Explicit ownership and mode checks at start-up; tests run as a non-member user |
| Licensing drift | `licensing.toml` plus CI; `septuvo-ipc` classification approved by this work order |
| Scope creep toward a tunnel | Out of scope above; any need for it is a stop-and-ask |
