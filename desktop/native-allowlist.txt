# Native-code allowlist for the Septuvo VPN desktop app (D-005, D-015, N4-01).
#
# Septuvo-authored code is Rust (D-005); external components may be in any
# language, but each is reviewed before adoption (D-015). Read by
# crates/septuvo-native-gate (CI job "desktop"): every crate cargo builds for
# x86_64-unknown-linux-gnu is inspected, and anything that could compile,
# bundle, link or load non-Rust code fails the build unless an entry below
# lists it with its reason. Today every entry is (a) an operating-system
# library or (b) inert in this build: nothing is compiled from C/C++.
# Crate-specific entries that stop matching fail too, so this list cannot
# grow stale. Evidence: docs/reviews/rust-gui-evaluation.md and
# docs/reviews/dependency-review-desktop.md. Changing this file is a
# dependency decision (D-015): it needs the owner's approval.
#
# Format: <kind> <fields> -- <reason>
#   build-tool <crate> <tool> unless-feature F | if-feature F | query-only
#   link <crate> <library>        library named in the crate's sources
#   binary <crate> <path>         binary file shipped inside the crate
#   not-loaded <crate> <file>     library name mentioned but never loaded
#   dlopen <file>                 OS library that may be loaded at run time
#   needed <soname>               OS library a built binary may need
#   (also: links <crate> <value>, command <crate> <program>; none are needed)

# --- Native build tools present but inert -----------------------------------
build-tool wayland-backend cc unless-feature log -- its build script compiles two C log shims only when feature `log` is on; it is off, so `cc` is never called
build-tool wayland-sys pkg-config if-feature dlopen -- with `dlopen` on, its build script returns before probing or linking anything; libwayland is loaded at run time instead
build-tool x11-dl pkg-config query-only -- its build script only asks pkg-config where the system's X11 libraries are installed (`libdir`), to load them at run time; it compiles nothing and links only libdl (below)

# --- Libraries named for linking --------------------------------------------
# The system C library on Linux (glibc: c, m, rt, pthread, dl, util). The same
# libraries every Rust program on Linux uses, septuvod included.
link libc c -- system C library (Linux and other Unix targets)
link libc m -- system C library maths (part of glibc)
link libc rt -- part of glibc on Linux
link libc pthread -- part of glibc on Linux
link libc dl -- part of glibc on Linux (dynamic loading)
link libc util -- part of glibc on Linux
link x11-dl dl -- `cargo:rustc-link-lib=dl` on Linux: glibc's dynamic loader, used to load the system's X11 libraries
link x11-dl c -- `cargo:rustc-link-lib=c` only for FreeBSD/DragonFly targets; on Linux the build script emits only `dl`
